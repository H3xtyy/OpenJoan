# src/lib/d3dx8

The D3DX8 code statically linked into joan.exe: math, matrix stack, error strings, buffers and the texture loaders. Each
`.cpp` names the original library sources it covers (`re/attribution.csv`, `lib/d3dx8/...`). Float arithmetic follows the
x87 code at 24-bit precision through [`src/fp/pc24.hpp`](../../fp/README.md).

| File | What |
|---|---|
| `math_matrix.cpp`, `math_geometry.cpp` | `d3dx8math.cpp`: matrices, vectors, quaternions, planes, geometry |
| `objects.cpp` | matrix stack, `ID3DXBuffer`, `D3DXGetErrorStringA` |
| `texture_api.cpp`, `texture_from_file.cpp`, `texture_in_memory.cpp` | `d3dx8tex.cpp`: `D3DXCreateTexture*`, `D3DXCreateTextureFromFileInMemoryEx` (0x00765258) |
| `helpers.cpp` | shared helpers of the above |

The texture loaders have a second, bit-exact implementation used by the renderer ([`src/render/image.*`](../../render/README.md)).

The function table below is generated from the registrations (`python3 tools/module_table.py src/lib/d3dx8 --write`; the tool cannot read the registration of `D3DXCreateTextureFromFileInMemoryEx`, whose address is written as an expression, so its row was filled in by hand: re-check it after regenerating).

Verification: the replay (matrix results feed game state), the smoke checklist. Library-owned vtable data was dropped from
the image.

See also: [`src/lib/README.md`](../README.md).
