# src/runtime/loader

The start-up of `openjoan`: the executable's `main`, the relocation of the committed data image, and the table of imports
answered by our code. Described as part of [`src/runtime`](../README.md); the start-up sequence is
[`docs/ARCHITECTURE.md`](../../../docs/ARCHITECTURE.md) section 3.

| File | What |
|---|---|
| `joan_re.cpp` | `main` -> `run()`: game folder, settings, data image, stray guard, imports, code slots, then the original's CRT entry `fn::WinMainCRTStartup` |
| `data_image.{hpp,cpp}` | relocates the stored pointers of `joan_image` to the object's address (`data_image::relocate`, `relocate_code`) and checks that every dead range lies inside its section (`check_sections`); `[Loader] PoisonDead=1` fills dead ranges with 0xCD |
| `import_overrides.{hpp,cpp}` | the imports of joan.exe that `openjoan` answers with its own functions; modules register entries, the loader consults the table |
| `dead_imports.inc` | generated by `re/gen_dead_imports.py` from `src/**`: imports nobody answers, which trap |
| `joan_re.rc`, `openjoan.ico` | Windows resources: version information and OpenJoan's own icon; the icon is drawn by `tools/make_icon.py` |

`data_image.cpp` is also linked into `data_image_reference_test` (`tests/`).

Verification: `data_image_reference_test` (ctest), the smoke checklist, the replay reference runs.
