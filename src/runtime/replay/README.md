# src/replay: record / replay with per-frame state hashes

The verification tool of OpenJoan: a recording holds every nondeterministic input the game received in a session
and a hash of the game state at every presented frame; a replay feeds the same inputs back and compares the hashes.
A change to game code is behaviour-free when the reference recording replays with exit code 0. Procedure: `docs/CONTRIBUTING.md`; options: `src/openjoan.ini` `[Debug] Record / Replay / Replay*`.

## Files

| File | What |
|---|---|
| `replay.hpp` | the public API: `install()` (from `host::start`, after every other slot change), `tsc()` / `cpu_tsc()` (the game's rdtsc is an input), `input_call()` (the SDL keyboard / mouse / pad reads), `wants_deterministic_heap()`, `active()`, `describe_code()` |
| `replay.cpp` | state, options (`[Debug]` keys and `--record FILE` / `--replay FILE`), the environment fingerprint and the save folders carried in a recording, the image hash (typed scheme + heuristic pointer positions), frame boundaries, divergence reports, `<recording>.report.txt`; `install()` |
| `imports.cpp` | one wrapper per intercepted import of the original (time, waits, files, messages, window, OpenAL, Direct3DCreate8): installed into the import slots inside `joan_image`, which hold the platform layer's functions (every platform) or the system's DLL (Windows, where a DLL is still loaded) |
| `com.cpp` | wrappers of the Direct3D 8 object methods (adapter queries, device state, `Present` = the frame boundary) by vtable patch, and of the platform layer's input reads |
| `sys.hpp` / `sys.cpp` | the recorder's **own** system services, portable: thread id, last-error guard, command line, executable range and stamp, committed memory regions (VirtualQuery walk / `/proc/self/maps`), fault-safe reads, clocks, files of the game folder (case resolved on Linux), symbol names (dbghelp / dladdr), stack capture. Added in Phase 1 (2026-10-29) when the recorder was made to build on Linux |
| `ids.hpp` | the `Id` of every intercepted call: its position is stored in recordings, so the list is append-only |
| `internal.hpp` | what the three recorder files share (record / play primitives, window procedure proxy, frame hashes) |
| `stream.hpp` / `stream.cpp` | the recording file format (header, Call / WndProc / Apc / Frame / Snapshot / Env / End events), writer, reader, hash helpers; platform independent |
| `typed_hash.hpp` / `typed_hash.cpp`, `hash_types.inc` | the typed scheme of the image hash: which bytes of `.data` / `.bss` are pointers (normalised), typed data (compared as it is) or untyped (heuristics); `hash_types.inc` is generated by `re/replay/gen_hash_types.py` from `src/data/layout.hpp` |
| `hash_types_check.cpp` | compile-time check of `hash_types.inc` against the layout |
| `x86_view.hpp` | the x86-layout view of `joan_image` for the hash on x64 |

## How it works on Linux (Phase 1)

The loader loads none of the original's DLLs on Linux: every import slot holds one of our functions
(`platform/`, `lib/imports`, `lib/openal`, `gl/`). The recorder therefore wraps exactly the same slots it wraps on
Windows, the recording format is the same, and a recording made on one OS describes the same calls as one made on
the other (`exe_stamp` is 0 for an ELF; the environment fingerprint lower-cases paths and uses `\` separators as
on Windows). Windows-only diagnostics: `ReplayWatch` (hardware write watchpoints) and `ReplayHashHeap` (the CRT
heap walk); both log that they are off elsewhere.

Verified 2026-10-29 on the `linux-x86` build: a headless record / replay (loader and start-up, 0 frames) and a
40-second on-screen recording closed through the window manager replay with exit 0;

## Known issues

- Our render features must decide by frames, not wall-clock time:
  the stream cache's time-based eviction made replays of the first reference recording diverge in the engine's
  ring cursors and statistics (fixed 2026-10-29, `[Debug] ReplayDumpPage` added for the diagnosis).
- A recording must not depend on where glibc puts our own allocations: the recorder masks a 4-aligned word that lies
  in a block mapped at an earlier frame but freed since (`g_ever_mapped`, a pointer the game kept past a release).
  Recordings made before 2026-10-29 21:30 hashed such a word raw (0x00a56794 of the PANEL sprite set, frame 9124
  of `ref-x86-2026-10-29.rec`), so any change of our heap use (the icon's SDL surface) made them diverge
  there; the word is also on the default skip list now. Re-record after this fix.
- The CRT's program path (`_pgmname`, 0x00a6b43c) is part of the hashed `.bss`: recordings made before the Phase 1
  rename replay only from the same folder by an executable named `joan_re`. It is on the default skip list from
  2026-10-29 on (`kDefaultSkipTyped`), so later recordings are independent of the folder and the executable's name.

- `ReplayHashBackBuffer` samples the back buffer through the Direct3D 8 surface interface of our GL device; it is
  only comparable on the same machine and driver.
- A recording that ends by a kill (no End event) replays up to its last event and reports where it stops; quit the
  game from its menu to end a recording cleanly.
